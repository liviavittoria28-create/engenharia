01 · ENGENHARIA DE SOFTWARE

Definições, camadas e atividades principais.

O QUE É ENGENHARIA DE SOFTWARE?

Segundo Sommerville (2007):

"Disciplina de engenharia relacionada com TODOS os aspectos de software, desde a especificação até a manutenção."
Objetivo: proporcionar técnicas para criação, aperfeiçoamento e implementação de sistemas com alta qualidade.

AS 4 ATIVIDADES PRINCIPAIS

EspecificaçãoDefinir o que o software deve fazer.
DesenvolvimentoConstruir o software.
ValidaçãoVerificar se atende ao esperado.
EvoluçãoManter e adaptar após a entrega.

AS CAMADAS (PRESSMAN, 2006)

Foco na qualidade — base de tudo
├─ Processos — guia para construir software
├─ Métodos — tarefas técnicas
└─ Ferramentas — apoio automatizado
Pegadinha: Levantamento de requisitos é MÉTODO. Modelo Cascata/Incremental são PROCESSOS. Compilador é FERRAMENTA. Base = FOCO NA QUALIDADE.

PROBLEMAS COM SOFTWARE

❌ NÃO FUNCIONAM

Levantamento de requisitos ineficiente.

💸 CUSTO MAIOR

Retrabalho, requisitos mal definidos.

🔧 MUDANÇAS GERAM PROBLEMAS

Código pouco manutenível.

⏰ FORA DO PRAZO

Má gestão de projeto e escopo.

02 · REQUISITOS DE SOFTWARE

Funcionais × Não funcionais × Regras de negócio.

REQUISITOS FUNCIONAIS

Funcionalidades solicitadas pelos usuários. Descrevem O QUE o sistema deve fazer.

Regra de ouro: se a frase descreve uma ação do sistema, é requisito funcional.

REQUISITOS NÃO FUNCIONAIS

Atributos de qualidade. Descrevem COMO o sistema deve se comportar.

Pegadinha: segurança e usabilidade NÃO são funcionalidades — são atributos de qualidade (RNF).

REGRAS DE NEGÓCIO

Restrições impostas pelo domínio do negócio.

Exemplo: RN01 — Permitir escolha de período de datas para consulta.

COMPARATIVO RÁPIDO

TIPOPERGUNTA-CHAVEEXEMPLO
FuncionalO que o sistema faz?Cadastrar cliente, emitir relatório
Não funcionalComo se comporta?Segurança, desempenho, usabilidade
Regra de negócioQue restrição o negócio impõe?Consulta só por período de datas

04 · MODELOS DE PROCESSO

Cascata × Prototipação × Incremental.

MODELO CASCATA

Requisitos → Análise → Projeto → Codificação → Teste → Manutenção

✅ VANTAGENS

Simplicidade, etapas bem definidas.

❌ DESVANTAGENS

Usuário só vê na entrega; requisitos "não podem" mudar.

MODELO DE PROTOTIPAÇÃO

Usado quando o problema não é bem compreendido. Valida requisitos via interações com o usuário.

Desvantagem: desenvolvedor ignora aspectos desconsiderados no protótipo.

MODELO INCREMENTAL

Dividir para conquistar — entregas parciais desde o início.
Desvantagem: dificuldades de integração entre módulos/sistemas.
